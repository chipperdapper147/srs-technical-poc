# SRS: language-learning tools

Prototype suite of spaced-repetition (SRS) language-learning tools. The first
tool is a **typed-recall vocabulary trainer**: it introduces new words, has you
type each one, then schedules reviews with [FSRS](https://github.com/open-spaced-repetition/ts-fsrs).

See [`docs/decisions.md`](docs/decisions.md) for why things are the way they are.

## Stack

| Layer      | Choice                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| Runtime    | Node 24 LTS (runs `.ts` natively via type stripping), pnpm workspaces + Turborepo                         |
| Database   | Postgres 18 (Docker Compose locally)                                                                      |
| Schema     | [Atlas](https://atlasgo.io): declarative `db/schema.sql` → versioned migrations in `db/migrations`        |
| API        | Fastify 5 + `fastify-type-provider-zod`, Kysely (types generated by `kysely-codegen`), OpenAPI at `/docs` |
| Web        | Next.js 16 (App Router), Tailwind 4, shadcn/ui (Base UI), TanStack Query                                  |
| Shared     | `@app/shared`: Zod contracts + answer grading, used by both sides                                         |
| Scheduling | `ts-fsrs` v6 (FSRS-7 model)                                                                               |
| Tooling    | TypeScript 6, Biome (lint + format), Vitest, GitHub Actions                                               |

## Layout

```
apps/api         Fastify API (src/routes, src/srs.ts, src/import.ts, test/)
apps/web         Next.js app (src/app, src/lib/study-session.ts, src/components/ui)
apps/e2e         Playwright tests: pages/ (page objects), tests/ (specs), support/ (fixtures)
packages/shared  Zod contracts + grading (imported as TS source)
db/schema.sql    Desired schema (edit this)
db/migrations    Generated, committed migrations (never edit)
db/seed          Sample course CSV
scripts/verify/  `pnpm verify`: change classes and verification rules (rules.ts), runner
scripts/         db-check.sh (CI schema guard), check-commit-messages.sh (no session links)
.githooks/       pre-commit (Biome), commit-msg and pre-push guards, enabled by `pnpm install`
docs/            decisions.md, verification.md, adr/
```

## Getting started

Prerequisites: Node 24 (`.nvmrc`), pnpm 10 (`corepack enable`), Docker, and the
[Atlas CLI](https://atlasgo.io/getting-started#installation)
(`curl -sSf https://atlasgo.sh | ATLAS_VERSION=v1.3.8 sh`, the version CI pins).

```sh
cp .env.example .env
pnpm install
pnpm db:setup        # start Postgres 18, apply migrations, seed the sample course
pnpm dev             # API on :4000 (docs at /docs), web on :3000
```

## Common tasks

| Command                                        | What it does                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| `pnpm dev`                                     | Run API and web in watch mode                                                         |
| `pnpm verify` / `pnpm verify plan`             | Run / show the checks this diff requires (see `docs/verification.md`)                 |
| `pnpm test`                                    | All tests (API tests use `TEST_DATABASE_URL`; Postgres must be running)               |
| `pnpm e2e`                                     | Playwright browser tests (starts API + web unless already running; needs a seeded DB) |
| `pnpm e2e:scratch [file]`                      | Throwaway specs in `apps/e2e/scratch/` (git-ignored, never in CI); see its README     |
| `pnpm typecheck` / `pnpm lint` / `pnpm format` | Types, Biome check, Biome autofix                                                     |
| `pnpm db:diff <name>`                          | After editing `db/schema.sql`: generate a migration                                   |
| `pnpm db:migrate`                              | Apply pending migrations to `DATABASE_URL`                                            |
| `pnpm db:codegen`                              | Regenerate `apps/api/src/db/types.ts` from the migrated DB                            |
| `pnpm db:check`                                | Validate migrations and confirm they match `schema.sql` (runs in CI)                  |
| `pnpm db:seed`                                 | Load the sample course (idempotent)                                                   |
| `pnpm api:openapi`                             | Regenerate the committed OpenAPI snapshot `apps/api/openapi.json`                     |

First e2e run: `pnpm --filter @app/e2e exec playwright install chromium`, or set
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an existing Chromium binary.

Schema change loop: edit `db/schema.sql` → `pnpm db:diff add_thing` →
`pnpm db:migrate` → `pnpm db:codegen` → commit all three.

## Importing words

Create a course, then paste or upload a CSV on its page:

```csv
unit,term,definition,alternatives,notes
Greetings,hola,hello,,
Around town,el ordenador,computer,la computadora|computadora,"Spain vs Latin America"
```

`term` is what the learner types (target language), `definition` is the prompt,
`alternatives` are other accepted answers separated by `|`.
